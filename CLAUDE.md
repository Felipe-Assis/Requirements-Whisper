# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"The Requirements Whisperer" (`config.name`) is an educational Ren'Py visual novel built as a UFRJ Game Design course project. The player is an intern living through the full software-engineering lifecycle (requirements, specification, design, coding, testing, deploy) over 8 in-game weeks, while choices affect friendships, learning records, achievements, and the ending. The job picked in `scene_1_quarto` selects one of three routes, each with its own company, team, and story: **saúde** (clinical web system ByeByeFumo, the original 22 scenes), **startup** (Trocado, a student expense app; 18 scenes `st_*`) and **corporativo** (Grupo Vértice, the legacy ticket system SGC and the new Farol module; 18 scenes `co_*`). Route bibles live in `docs/rotas/`; the integration plan and its decisions in `docs/plans/2026-11-02-integracao-rotas.md`. The narrative content and all UI strings are in Brazilian Portuguese. Originally developed on Ren'Py 8.3.7; migrated to Ren'Py 8.5.3 (Python 3.12) on the `migracao-8.5.3` branch (SDK at `C:\Program Files (x86)\renpy-8.5.3-sdk`; keep the 8.3.7 SDK for rollback). `config.version = "1.1"`; minimum Ren'Py 8.2+ / Python 3.8+.

## Common commands

There is no Makefile, npm, or CI — everything goes through the Ren'Py SDK launcher. The project root passed to the launcher is the repo root (the folder containing `game/`), NOT the `game/` folder itself.

GUI workflow (primary, on Windows): launch `renpy.exe` from the SDK, then in the launcher select/add this repo as a project and use Launch Project / Build Distributions / "Check script (lint)" / "Force recompile".

CLI equivalents (run from the SDK directory; `<project>` = absolute path to this repo root):
- Run the game: `renpy.exe "<project>"` (or `./renpy.sh "<project>"`)
- Lint (do this before committing script changes): `renpy.exe "<project>" lint`. On Windows `renpy.exe` writes nothing to the console, so to actually see results run lint through the SDK's embedded Python: `& "C:\Program Files (x86)\renpy-8.5.3-sdk\lib\py3-windows-x86_64\python.exe" "C:\Program Files (x86)\renpy-8.5.3-sdk\renpy.py" "<project>" lint` (results also land in `errors.txt`).
- Compile `.rpy` -> `.rpyc`: `renpy.exe "<project>" compile`
- Build distributions: `renpy.exe "<project>" distribute` — `project.json` targets `pc`, `mac`, `win`, `linux`, with `force_recompile: true` and `build_update: false`. `options.rpy` sets `build.name = "TheRequirementsWhisperer"`; `progressive_download.txt` configures RenPyWeb progressive download.

Tests run inside the engine (Ren'Py `testsuite`/`testcase`) from `game/tests/` (excluded from builds via `build.classify` in `options.rpy`): `& "<sdk>\lib\py3-windows-x86_64\python.exe" "<sdk>\renpy.py" "<project>" test --savedir "<project>\.test-saves"`. They cover route dispatch, the learning mechanics, offline chat, `set_available` per route and one end-to-end playthrough per route. `game/tests/autopiloto.rpy` + `autopiloto.ps1` drive full playthroughs (first/last/seeded random choices, forced branches via `RW_AUTOPILOTO_FORCAR`) and write JSON reports to `.test-saves/autopiloto/`; run `powershell -File game/tests/autopiloto.ps1` after changing scenes. Lint must stay 100% clean and all tests must pass. `tools/build-windows.ps1 -SdkPath <sdk>` lints, builds the Windows ZIP and writes its SHA256 to `dist/`. Ren'Py also writes diagnostics to `log.txt`, `errors.txt` (lint/parse errors), and `traceback.txt` (runtime exceptions) at the repo root — read these to debug. Note: any `traceback.txt`/`errors.txt` committed in the repo are stale historical artifacts that may not match current code (e.g. the chat now detects web via `renpy.variant("web")`, not the old `import emscripten` probe); regenerate them by running, don't trust the committed copies.

## Architecture

Top-level `game/` layout (after the Fase 1 refactor): `story/act{1..5}_*/` + `story/epilogue/` (scenes), `logic/` (mutable state defaults & helpers), `data/` (static content: characters, names, items, audio, backgrounds), `ui/styles/` (transforms), and `scripts/mechanics/` (the inventory/contacts/clock/chat screens). Entry points `script.rpy`/`screens.rpy`/`options.rpy`/`gui.rpy` stay at the `game/` root.

### Flow: one `call` chain per route
`game/script.rpy` defines `label start`: it calls `scene_1_quarto` (profile + job choice, which sets `chosen_job`), then dispatches on `chosen_job`: `"startup"` → `call rota_startup` (`game/story/rota_startup/rota_startup.rpy`, scenes `st_01`…`st_18`), `"corporativo"` → `call rota_corporativo` (`game/story/rota_corporativo/`, `co_01`…`co_18`), otherwise the original health chain `scene_3_reuniao_inicial` … `scene_21_avaliacao_final` (unchanged, same `from` labels, so old saves keep their return points). All routes end in the shared `scene_epilogo_conquistas_final`. `scene_1_quarto` ends with `jump scene_2_escritorio`, which plays the health arrival and `return`s to `start`; for the other routes it just returns (their arrival is the first scene of their chain). `scene_2_escritorio` stays out of the chain on purpose. Health scenes live in `game/story/act{1..5}_*/scene_*.rpy`, one label per file. Each new route has an `estado_<rota>.rpy` with all its `default`s (prefix `st_`/`co_`), helpers and its records/achievements/final rule registered into `ROUTES` at `init 2`. The epilogue offers replay (`renpy.full_restart()` — a clean restart that re-inits every `default`) / credits / quit. To change story order, edit the `call` list in `script.rpy` — scenes do not auto-discover each other.

### State model: flat `default` globals, no classes
Game state is a large set of module-level `default` variables under `game/logic/` (static content data lives alongside in `game/data/`), all living in Ren'Py's `store` and auto-included in saves:
- `logic/state_flags.rpy` — `item_*` booleans (inventory), per-contact `contato_*` (unlocked at all) and `disponivel_*` (reachable right now) booleans.
- `logic/state_time.rpy` — the in-game clock (`game_hour`, `game_minute`, `show_clock`) with `set_time()` / `advance_minutes()` helpers.
- `logic/state_progress.rpy` — `progresso_roteiro`, `nivel_estresse`, `energia_diaria`, plus chat runtime state (`chat_history`, `user_input`, `is_waiting`, `server_response`, and the transient `pending_response` buffer). `logic/state_player.rpy` holds the remaining player-scoped defaults.
- `logic/friendship.rpy` — `amizade_*` floats (0–10) per character (friendship/affinity).
- `data/characters.rpy` — `Character()` objects and sprite `image` mappings; `data/character_names.rpy` — character display names (`NOME_*`) and colors (`COR_*`). Reusable sprite-position transforms (`left_zoom`, `center_zoom`, `right_zoom`, etc.) live in `game/ui/styles/sprite_transforms.rpy`. Always reference names via the `NOME_*` defines, never hardcode "Emily"/"Lucas".

### Two flag layers gate the phone/chat
This is the non-obvious core mechanic. Each contact has BOTH a `contato_<id>` (have you met them — show in the contacts grid) and a `disponivel_<id>` (can you message them *now*) flag. Scenes flip `disponivel_*` at their top to model "you can't text someone who's in the same room" (e.g. `scene_11_almoco_equipe` sets all to `False`; `scene_13_retorno_casa_sem3` sets all to `True`; `scene_14` sets a mix). In the contacts UI, an unavailable contact is rendered grayed-out and non-clickable. When editing a scene, call `set_available(...)` (in `logic/state_flags.rpy`) at the label start, passing the ids who are NOT in the room (and can therefore be messaged) — it resets the `disponivel_*` of `route_contact_ids()` for the current route and enables only the ids passed (`set_available('all')` = everyone in the route). On health that is still only the 8 developers (doutora availability is set by explicit lines, e.g. in `scene_21`; `scene_5`/`scene_7` keep partial inline blocks); on the new routes it covers team and stakeholders. `set_available` also clears `chat_amizade_dada`, so chatting gives +1 friendship only once per contact between two `set_available` calls (no farming).

Routes are described in `game/data/routes.rpy`: `ROUTES[rota]` holds `empresa`, `team`, `stakeholders`, `contacts_order`, plus `records`, `achievements` and `final` registered by each route; helpers `current_route()`, `route_data()`, `route_team()`, `route_contact_ids()`, `route_contacts_order()`. The contacts grid iterates `route_contacts_order()`.

Helpers (in `game/logic/`, called from scenes via `$`):
- `add_contact("developer_ai")` — unlocks a contact (sets `contato_developer_ai = True`, adds to the `contacts` set, notifies). [`logic/friendship.rpy`]
- `add_friendship_point("developer_ai", amount)` / `get_friendship_point(id)` — adjust/read `amizade_*` (clamped 0–10). [`logic/friendship.rpy`]
- `friendship_color(level)` — bar color for a friendship level, used by the contacts UI. [`logic/friendship.rpy`]
- `add_to_inventory("notebook")` — sets the matching `item_*` flag. [`logic/inventory.rpy`]

Contact/character ids are the canonical keys used everywhere: health `developer_ai`, `developer_requirements`, `developer_coding`, `developer_management`, `developer_quality`, `developer_project`, `developer_security`, `developer_test`, `doutora_1`, `doutora_2`; startup `st_mentora`, `st_techlead`, `st_mobile`, `st_qualidade`, `st_ceo`, `st_estudante`; corporativo `co_mentora`, `co_legado`, `co_dev`, `co_qualidade`, `co_supervisora`, `co_solicitante`. Adding a new contact means touching all layers: a `Character`/image in `data/characters.rpy` plus `NOME_*`/`COR_*` in `data/character_names.rpy`, `contato_*`/`disponivel_*` defaults (`logic/state_flags.rpy`) and `amizade_*` (`logic/friendship.rpy`), an `AMIGOS_DATA` entry in `data/friends_data.rpy` (with `assistant_id`, or `assistant_id: None` plus an `offline` list of scripted replies) and the id in the route's `team`/`stakeholders`/`contacts_order` in `data/routes.rpy` (health keeps using `DEVELOPERS`/`CONTACTS_ORDER`).

### Learning mechanics (ported from the short demo)
`logic/learning.rpy` + `scripts/mechanics/learning_activities.rpy` + `notebook_screen.rpy`:
- `registrar(rid)` marks one of the route's 8 notebook records as discovered (`registros` set); the notebook item in the Mochila opens `screen notebook_registros`.
- `decisao(did, adequada)` records only the first attempt of a teaching decision in `aprendizagem` (adequate alone vs. needed guided review). Teaching menus follow one pattern: 1 adequate option + 2 plausible distractors, each distractor explains its concrete consequence, then a guided review — never a penalty. New routes wrap this in `st_decidir(...)` / `co_acerto(...)`/`co_erro(...)`.
- `call exercicio_escrita(eid, pedido)` — free writing of a requirement + acceptance criterion with draft review and a 4-point self-check, stored in `escritas[eid]` (text escaped, resumable). The game never grades the meaning of free text.
- `call atividade_planejamento(pid, itens, necessarios, capacidade=2)` — capacity planning; returns the coverage in `_return`, stored in `planejamentos`.
- The epilogue shows `screen resumo_rota`: company, achievements (`achievement_unlocked`), records N of 8, decisions alone vs. with support, confirmed writings, and states that finishing does not certify mastery.
- Accessibility preferences in `screens.rpy`: larger text (`persistent.texto_maior`), instant text, transitions off; Mochila and notebook work by keyboard. The contacts grid is data-driven (a `contact_tile` loop), so no per-contact UI block is needed.

### UI mechanics (`game/scripts/mechanics/` screens; styles in `game/ui/styles/`)
- `inventory_screen.rpy` — the "Mochila" screen + persistent `inventory_button` (gated by `inventory_enabled`). Data-driven: `ITENS_ORDER`/`ITENS_DESC` + a `inventory_tile(item_id)` loop. The phone (`item_celular`) opens `contacts_screen`.
- `contacts_screen.rpy` — the contacts grid. Data-driven: `for cid in route_contacts_order(): use contact_tile(cid)`; an available tile sets `amigo_selecionado` and `Call`s `chat_amigo` (a `Jump` would end the scene that did `call screen contacts_screen`; covered by a regression test).
- `clock_screen.rpy` — `top_right_clock` overlay driven by `game_hour`/`game_minute`/`show_clock`.
- `chat_screen.rpy` — chat UI only (`screen chat_with_backend` + `label chat_amigo`); the HTTP client is in `python/chat_backend.rpy`, styles in `ui/styles/chat_styles.rpy`.

### AI chat: live external backend (load-bearing)
The chat is NOT scripted dialogue — it calls a remote LLM-assistant service over HTTP, split across files:
- `data/friends_data.rpy` — `AMIGOS_DATA` maps each contact id -> `{name, portrait, assistant_id, desc}` (`asst_...` ids); also bootstraps `current_assistant_id` (intentionally NOT a `default`).
- `python/chat_backend.rpy` — the client: `is_web()` (now `renpy.variant("web")`), the single `normalize_resposta()`, the desktop (`requests` + `threading`) and web (`js.fetch`) sends, `send_and_update_chat()`, plus the main-thread drain (`process_respostas` → buffer; `drain_pending_response`) and the `__reset_chat_transient` after-load callback. The endpoint is built from one `define BACKEND_BASE_URL`.
- `python/user_id.rpy` — `generate_user_id()` (`init -1`) + `default user_id`, called from `label start`.
- `mechanics/chat_screen.rpy` — `label chat_amigo` looks up the friend, sets `current_assistant_id`, gives +1 friendship once per contact since the last `set_available`, and shows `screen chat_with_backend`.
- Offline contacts: the remote assistants only know the health project, so the 12 startup/corporativo characters have `assistant_id: None`; `send_and_update_chat` then answers locally on the main thread with the next line of the character's `offline` list (`chat_offline_idx`), with no network and no `is_waiting`.
- Desktop runs the request on a background `threading.Thread`; `is_web()` branches to a JS `fetch` path (web currently returns a "download the game" notice). `requests` relies on the SDK's bundled Python (not vendored). **Threading rule (8.5-safe, load-bearing):** the worker thread must NOT mutate `store` — `process_respostas` only writes the transient `pending_response` buffer and calls `restart_interaction()`; the `chat_with_backend` screen's `timer 0.1 repeat True` runs `drain_pending_response()` on the main thread, the sole place that appends to `chat_history` and clears `is_waiting`. `__reset_chat_transient` (an `after_load_callbacks` entry) wipes the transient chat state on load so a save made mid-"typing…" can't softlock the input.

When touching chat, keep the desktop/web split and the single `normalize_resposta` (the backend may return a string, a JSON list, or a stringified list). Remote responses arrive at runtime and are NOT statically translatable.

### Notes
- A root `.gitignore` ignores `*.rpyc`/`*.rpymc`, `game/cache/`, `game/saves/`, the diagnostics, and `.playwright-mcp/`. After renaming/moving `.rpy` files, delete stale `.rpyc` (or Force Recompile) before linting — orphaned compiled copies cause phantom "line id appears twice" errors.
- Audio: `define music_*` in `game/data/audio_library.rpy` (music files under `game/audio/music/`, SFX in `game/audio/effects/`); backgrounds in `game/data/backgrounds.rpy`; item images in `game/data/items.rpy`.
- i18n: UI/Python/`define` strings are wrapped in `_()` (dialogue/menus auto-extract); a language selector is in Preferences. Regenerate the locale skeleton with `renpy.exe "<project>" translate english` (the `tl/` tree is gitignored); `NOME_*` are translatable. Remote chat text is not statically translatable.
- Migration (8.5.3): `options.rpy` sets `config.zoom_zaxis = False` and `config.old_show_expression = True` explicitly (not via `config.version` parsing) to preserve 8.3.7 sprite framing and the legacy `show expression` used by item pop-ups — don't drop these or the `*_zoom` transforms and item shows will shift/break. `im.Scale` in `data/backgrounds.rpy` still works under 8.5 (optional follow-up to native scaling).
- Analysis + execution plans (migration to 8.5.3, the refactor, critical bugs, the route integration) live in `docs/` — see `docs/README.md`.
- Art for the new routes (12 characters, 9 backgrounds, 8 product screens) was generated with Codex (`imagegen`) using existing sprites/backgrounds as style references, then normalized (sprites RGBA 1024x1536 with the same figure framing, portraits cropped from the neutral pose, backgrounds 1536x1024). Prompts and descriptions are in `docs/rotas/*-assets.json`. Keep that framing when adding art.
